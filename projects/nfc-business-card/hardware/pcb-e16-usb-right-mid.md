## 布局方案

板框仍为 **84 × 52 mm**，底边恢复直边，USB 缺口移到右边缘中部。

| 项目 | 数值 |
| --- | --- |
| 缺口 | 右边缘 **13 × 6.5 mm**，y = 9.5–22.5 mm，内缘 x = 77.5 mm |
| J1 | (78.5, 16.0) mm，插口朝 +x；内缘距封装原点 1.025 mm，沿用底边已验证的关系 |
| 连接器本体 | 板内约 2.1 mm，板外约 4.45 mm，外壳需要开口容纳外伸段 |
| U1 | (65.0, 8.0) mm，旋转 180°，模块天线端朝下板边 |
| U1 天线净空 | x 59.75–70.25、y 0.25–2.55 mm，各层不铺铜、不放器件 |
| USB ESD/CC/VBUS | U5/U6 → (73.6, 16.6)/(73.6, 14.9)；R1/R2 → (71.9, 14.75)/(71.9, 17.75)；C1/C3 → (73.6, 12.6)/(71.9, 20.6) |
| U1 去耦 | C5/C6/C7 → (61.0/63.4/65.8, 17.2)，贴在模块电源脚一侧 |

移动清单与移动前位置：J1 (49.5, 5.5) → (78.5, 16.0)；U1 (76.2, 12.7) → (65.0, 8.0)。其余 9 个器件都是随 USB 位置和 U1 新位置一起调整的小元件。

## 天线方向依据

Raytac MDBT50Q Rev L 原厂图纸（[本地 PDF](../downloads/raytac_mdbt50q_rev_l.pdf) 第 8 页，已渲染核对）指出：模块为 15.5 × 10.5 × 2.0 mm，**天线在无引脚的一端**；文档 2.3 节要求天线对应位置**各层都不得铺地**，并建议模块靠板边布置。

- 快照里 U1 的引脚排布与图纸一致：引脚 1 在左列顶端、55 在右列顶端、15–33 在底边，因此封装局部 **+y 就是天线端**。
- 新位置旋转 180°，天线端朝下，天线区落在 y 0.25–2.55 mm，距板边 0.25 mm；相邻 8 mm 内没有连接器金属壳。
- 若把天线端朝右（+x），它会正对右侧 USB 金属壳，因此不采用。

## 离线校验结果

校验比较"E15 原布局"和"本方案"两套真实焊盘坐标，使用同一套规则（焊盘间 0.20 mm、外形间 0.30 mm、NFC 保留区、天线净空）：

| 结果 | 内容 |
| --- | --- |
| 新增几何冲突 | **0** |
| 沿用项 | J2 与 C16/C17 焊盘贴近（E15 原布局已有，不是本次引入） |
| 顺带解决 | R1 原来压在底边 USB 缺口上；J1 与 R1 焊盘原来过近 |
| 仍存在的机械项 | 连接器**前侧锚脚**仍落在缺口范围内；E15 底边版本同样如此，属于待用连接器剖面容差确认的既有问题 |

缺口形状本身仍按"缺口内缘＝连接器 PCB 边"的关系复制底边已验证的尺寸；GCT 推荐布局图给出的是板边直线 + 焊盘行 1.60 mm、锚脚 4×0.60，尚未得到可确认锚脚与缺口相对关系的剖面容差，因此本方案不擅自改锚脚或焊盘。

## 未完成项

1. **尚未写入 EasyEDA。** 本机 Run API Gateway 扩展未连上桥接服务；重连后才能在 E16 图页落盘、保存重开并跑原生 DRC。
2. **旋转方向待客户端确认。** 方案按逆时针为正计算（由 C0603/R0603 两个已旋转元件的焊盘方向反推）；落盘后必须回读焊盘位置核对。
3. **外壳开孔与外伸包络。** 连接器本体外伸约 4.45 mm，需要外壳右侧壁开口，并确认插拔包络不超出 84 × 52 外框。
4. **NFC 馈线路径。** U1 的 NFC1/NFC2 落在模块左下侧，到右上线圈约 25 mm，需按匹配网络一并规划。
5. **原生 DRC 与网表。** 移动只改位置，不改网络；仍需在客户端复核连接错误数量与槽边距分类结果。

## 早期试放记录

2026-09-22 早些时候已复制出 E16 图页（PCB UUID `2fe84861daa4cba5`）试放过一次 USB 小组，当时直接把 J1/U1 平移，得到 30 个普通间距错误、12 个同封装间距错误和 200 个连接错误，证明"只挪 J1"不可行。那一轮的坐标和 DRC 记录在 [e16-usb-right-mid-study.json](e16-usb-right-mid-study.json)；本页方案是它的修订版。

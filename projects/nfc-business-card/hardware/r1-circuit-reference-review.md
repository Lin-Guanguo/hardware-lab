### 新增建议：直接电池采样

R1 网表的 BAT_PACK_TBD 仅连接 U2.BAT 和 C3，MCU 的空闲 AIN 没有电池分压支路，也没有电量计。现有充电器有欠压保护；稳压输出跌落后也能观察到系统电压变化，但二者不等于直接读取电池电压、提前判断刷新余量或估算电量。

若需要低电量提示、刷新前判断电压或避免掉电重试，建议下一版预留分压与滤波，是否增加采样开关取决于待机电流预算。这里建议的是电压检测，不要求增加电量计，也不能把电压直接换算成准确百分比。具体阈值还需结合屏幕瞬态、电池内阻和 LDO 压差测量；仅测刷新前电压不保证整个刷新过程稳定。

### 新增归并项：充电和 USB 状态统一管理

充电电流、USB 输入限流、系统耗电是三个不同量。BQ25186 的默认输入限流为 500 mA，含义是限制上界，不代表实际一定消耗 500 mA。两个 5.1 kΩ CC 下拉完成受电端声明，不等于已经识别源端允许 1.5 A/3 A。bootloader 和应用需统一处理枚举前、配置后、USB suspend、拔线和看门狗复位，避免一阶段正确而另一阶段恢复默认值。

依据：[BQ25186](https://www.ti.com/lit/ds/symlink/bq25186.pdf) §6.5.1.8–9、[TI USB Type-C 说明](https://www.ti.com/lit/wp/slyy109b/slyy109b.pdf)第 4 页，以及[现有 USB/SWD 审查](r1-usb-swd-recovery.md)。这是一项待实现的固件约束；尚未测得违反 USB 电流要求。

## 已确认的缺口

### 1. 不加温度检测，落实 TS 固定电阻

- 用户明确选择省去电池温度检测，不再将增加热敏电阻或传感线列为整改要求。
- U2 BQ25186 的 pin 6（TS/MR）通过 `BAT_NTC_TBD` 接到独立 NTC 焊盘；当前 BOM 没有用于无 TS 配置的固定电阻。
- 原厂数据手册 §6.3.15.1、§7.2.1 明确规定：不使用 TS 充电控制时，TS 到 GND 接 10 kΩ 电阻。这是固定电阻，不需要贴电池或增加电池引线；不能将 TS 直接短接地，因为它还承担低有效 MR 功能。
- 悬空会产生 TS_OPEN_STAT，仅清除 TS_EN 不会消除开路状态。固定电阻方案避免依赖应用启动后才消除 TS 异常；不将其表述为具备电池温度保护。
- R7 将 CE 默认拉高，应用需要主动使能充电。首次启动、bootloader、应用复位及充电器看门狗恢复默认值后的行为，都要纳入固件验证。

待机低功耗不能确定电池允许的充电电流。最终限流仍以所选电池规格为依据；原有文档中的 0.5C 估算不能替代电池厂商数据。

### 2. 三颗屏幕电容属于官方资料差异，暂不要求改值

## 续审发现：低功耗与固件约束

### CE 拉低后，R7 可持续消耗约 330 µA

网表中 R7 = 10 kΩ，从 VDD_3V3 接 U2.CE / U1.P0.06。充电时 MCU 需要拉低 CE；若拔掉 USB 后仍保持输出低，电池会经 LDO、R7、MCU GPIO 持续供电。名义计算：3.3 V / 10 kΩ = 330 µA，即每天约 7.92 mAh，仅计算该支路。

BQ25186 手册 pin description 说明 CE 在 VIN 不存在时不影响充电器功能，但外部上拉电阻依然耗电。电池待机应使 CE 为高，或释放为高阻且关闭 MCU 内部下拉。现有电阻默认禁止充电的作用可保留，无需仅为这项风险先改阻值。这是确定存在的潜在电流通路，尚无成品固件，不能宣称已测得 330 µA 漏电。

### 普通待机不能直接采用充电器 Ship Mode

SW1–SW3 只接 MCU。BQ25186 的 Ship Mode 会断开 BAT 到 SYS，退出依靠有效 VIN 或 TS/MR 按钮；本板按键不接 TS/MR。因此进入该模式后，三个交互键不能恢复主电源。日常待机应保留 SYS，使用 nRF 的低功耗状态并配置按键唤醒；运输模式可以保留给需要插 USB 恢复的场景。此项无需增加复位键，沿用用户已确定的 SWD 救援安排。

### 缺少外部 32.768 kHz 晶振是固件配置约束

U1 pin 17/18（XL1/XL2）未连接外部晶振。Raytac Rev L 第 35 页说明模块内部有 32 MHz 晶振及 REG1 DC/DC 电感，32.768 kHz 可使用内部 RC；厂家出厂测试程序使用外部低频晶振配置。

bootloader 与应用都应按本板选择低频 RC，并按所选 Nordic 软件栈处理校准与精度；不能直接继承开发板的 LFXO 配置。REG1 DC/DC 可按原厂条件启用以降低运行功耗，无需为此补低频晶振。未将该板的晶振省略判成硬件错误。

### 屏幕示例的容错流程不应照搬

官方 ZIP 的 Arduino 示例默认为 BUSY 低有效，但规格书文字称高有效。代码的 `epdTryFixBusyPolarity()` 会在超时后翻转极性，再失败则设置 `gIgnoreBusy = true`；`epdDisplayImage()` 的多处 `epdWaitBusyStage()` 返回值未阻止后续命令。

这些属于上游示例行为，不是本板已存在的固件缺陷。移植时应由样板验证固定极性；超时进入错误处理，不自动忽略 BUSY 后继续刷新/断电。本轮未找到能替代样板验证的正式 BUSY 勘误。120000 ms 是示例超时，不是屏幕刷新时间。

## 待验证的电气风险

### 屏幕断电后的 GPIO 反向供电

U4 TPS22919 切断 `EPD_VDD`，QOD 接输出以进行关断放电；MCU 的 SPI、CS、DC、RESET 仍直接接屏幕。若屏幕断电时这些引脚保持高电平，存在从信号脚反向供电的风险。

固件需按屏幕驱动要求完成高压关断，再配置接口为合适的低电平或高阻状态，关闭不适用的上拉，最后关闭 U4；上电也需安排初始化顺序。测量屏幕关闭后的 EPD_VDD 和整板电流才能确认。R13 默认关闭 U4、R18 的 BUSY 上拉接在开关后的电源，这两点可保留。

### 低电量时的刷新供电余量

U3 TPS7A02 是 200 mA LDO，主控和屏幕共用其输出。当前缺少屏幕刷新峰值电流与实际电池内阻数据，无法证明余量充足，也不能直接判定 200 mA 不够。电池电压下降时，LDO 会进入压差不足区；这不等于电池到 3.3 V 就必然无法工作。

样板应覆盖实际允许的电池电压范围，测量冷启动、全屏刷新、无线活动重叠时的峰值电流及最低 VDD_3V3/EPD_VDD，再决定是否需要更换供电方案。

### USB VBUS 的保护覆盖

USB_VBUS 同时接 U2.IN 和 U1.VBUS。U5/U6 保护 USB 数据线与 CC，未覆盖 VBUS；BQ25186 的输入过压保护作用于其 SYS/BAT 路径，不能保护并联在输入端的 MCU VBUS。

这是保护覆盖的边界，不是普通 USB 连接必然出故障的证据。下一版需结合 MCU 的 VBUS 额定值、预期瞬态及布局评估专用 VBUS 保护；不能仅按标称“5 V TVS”选件而忽略实际钳位电压。

### 已知原型验证项

- NFC C23/C24 的 220 pF 仍为起始值，需带最终屏幕、电池、磁性材料及外壳调谐。网表中天线特殊连接表达不能直接当成物理短路；已有线圈连通性证据需保留。
- 当前没有独立的电池电压分压采样或电量计。若后续需要可靠的低电量提示，再定义指标并补设计；稳压后的 MCU VDD 不能直接代表电池电压。

## muxcard 中适合借鉴的部分

muxcard 的电源图使用 MCP73811、LM66100 和 NCP163；NFC 图采用 RC522 读写器。R1 的 BQ25186 电源路径、nRF52840 内置标签功能及独立屏幕电源开关符合当前名片用途，没必要为了外观相似就更换架构。

值得学习的是逐项验证待机状态、外设供电和真实装配，而不是按其元件清单复制。muxcard 自述仍是原型与持续开发项目，其显示屏、NFC 工作模式及制造约束与 R1 不同。

## 证据与检查范围

- 本地设计：[原理图导出网表](records/r1-schematic.enet)、[PCB 引脚](records/r1-pcb-pins.json)、[PCB 快照](records/r1-routed-snapshot.json)、[生产 BOM](production/r1/NFC-Card-R1-bom.csv)。结论针对这些已保存的导出记录；未检查编辑器中可能存在的未保存改动。
- [BQ25186 数据手册](https://www.ti.com/lit/ds/symlink/bq25186.pdf)：§6.3.8.1、§6.3.15.1、§6.5.1.8。
- [TPS7A02 数据手册](https://www.ti.com/lit/ds/symlink/tps7a02.pdf)：输出能力、压差及瞬态响应。
- [TPS22919 数据手册](https://www.ti.com/lit/ds/symlink/tps22919.pdf)：QOD 功能。
- [GDEH0154E01 本地原厂规格书](../downloads/gdeh0154e01.pdf)：第 7–8 页参考电路。
- [DESPI-E01 原厂电路缓存](../downloads/despi-e01-schematic.pdf)、[官方示例入口](https://www.good-display.com/companyfile/2062.html)及[本地 ZIP](../downloads/gdeh0154e01-esp32.zip)：Arduino 文件第 48–65、138–175、407–442 行。
- [Raytac Rev L](../downloads/raytac_mdbt50q_rev_l.pdf)：第 35、40 页。
- [muxcard](https://github.com/krauseler/muxcard) 的 README 与公开硬件 PDF（Power、Display、NFC）；读取日期 2026-09-24，未将其作为 R1 的器件级设计依据。

复核命令：

```sh
python3 projects/nfc-business-card/scripts/check-netlist-consistency.py --sch projects/nfc-business-card/hardware/records/r1-schematic.enet --pcb projects/nfc-business-card/hardware/records/r1-pcb-pins.json
```

结果：两侧均为 58 个器件、238 个引脚，pin/net mismatch 为 0。这只证明导出记录中的连接一致，不能发现参考值分歧、缺少 TS 固定电阻或电气瞬态问题。本轮未重新执行原生 DRC，也没有样板电气实测。
